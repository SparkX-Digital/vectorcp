# Public authoritative DNS — Unreleased 0.4.3

This optional development profile extends the private BIND preview. It serves
explicitly activated zones over UDP and TCP. It is not included in the immutable
0.4.2 download. Public delegation, independent nameserver availability and an
independent security/capacity assessment remain separate acceptance gates.

## Owner setup

Use the current reviewed source on the supported AlmaLinux 9 installation. Keep
the private preview until all nameservers, addresses and networking are ready:

```sh
bash deploy/dns-install.sh --apply
bash deploy/dns-public.sh --apply --public \
  --nameserver ns1.example.net --nameserver ns2.example.net \
  --listen-ip 192.0.2.10
```

Replace the example names and documentation address. Supply two to four distinct
full nameserver names and one to eight addresses actually assigned to active
server interfaces. Repeat `--listen-ip` for additional IPv4/IPv6 interfaces. The
loopback IPv4 listener is always retained for local verification. Wildcard,
multicast, link-local and unspecified addresses are refused. A server behind NAT
uses its assigned interface address here; its routed public address and port
forwarding must be configured separately. A configured public IPv4 is still
required by the existing website/zone creation workflow.

The helper changes the existing DNS service configuration and restarts that
service. It does not modify SSH, the panel listener, websites, host/provider
firewalls, NAT or registrar records. Permit inbound **UDP and TCP port 53** in
the appropriate host/provider firewall before delegation. The service must
already be installed. Both transports are checked on every selected interface
before the new profile is recorded as ready.

Nameservers need working addresses and consistent authoritative copies of the
zone. Two names on one server do not provide redundancy. This revision has no
secondary-server provisioning, transfer authorization or cluster replication;
independent copies need a separately managed arrangement. In-zone nameservers
also need registrar glue where required. Do not delegate a real domain until
every advertised nameserver independently returns the intended records.

The agent and all supplied service-profile helpers share a file lock in private
control state. New DNS writes are refused during profile maintenance. The helper
checks for active hosting jobs and active public zones. Unassigned interfaces or
invalid configuration fail before a new profile is accepted. Original files,
permissions and a manifest are retained under the root-private directory
`/var/lib/vectorcp/dns-profile-recovery/`. Ordinary failures restore those files
and restart the previous service. A failed rollback explicitly requires owner
inspection of that recovery directory; no successful result is reported.
Exit status 75 retains the maintenance marker to block further DNS mutations
until the owner has inspected and repaired the interrupted transition.

## Customer workflow

1. Choose the website in **DNS zones**, then create a draft zone. The initial apex
   A record uses the configured server IPv4. The profile does not infer working
   mail, SPF/DKIM/DMARC or application records.
2. Add or edit the complete record set. Supported types are A, AAAA, CNAME, MX,
   TXT, NS, CAA and SRV. Existing bounds remain: 100 editable records per zone,
   TTL 300–86400 seconds, printable TXT up to 255 bytes and 256 zones per server.
3. Put the displayed `_vectorcp.<domain>` TXT challenge at the current DNS
   provider. **Check ownership** requires the exact value through both fixed
   public resolvers, 1.1.1.1 and 8.8.8.8. Unavailable or mismatching responses
   fail closed. Responses may be cached; no DNSSEC validation claim is made.
4. Choose **Activate public hosting** and type the exact domain. Activation
   repeats ownership verification; the earlier check alone does not authorize
   publication. A/AAAA records must exist for nameserver names inside this zone.
   SOA, apex NS and the active ownership TXT are generated by VectorCP.
5. Verify the authoritative service from outside the server over both transports
   and check every nameserver before changing registrar delegation. Activation
   does not change registrar settings. Preserve a copy of the previous DNS zone.

An existing private or migrated zone remains a draft when the owner switches to
the public profile. Drafts are excluded from the running public zone list.
Ownership checks cannot be satisfied by an unactivated local draft. Active zones
include the managed ownership TXT so ownership can be checked again after
delegation; it is not an authentication credential.

Add, edit, delete, activation, deactivation and rebuild enforce website ownership,
inherited DNS feature permissions, account/reseller availability, CSRF and idle
customer state. Browser forms carry their original website and zone serial;
stale forms are refused. Older API add/delete requests without a serial remain
compatible; new clients should always send it. Record edits and public-state
changes require a serial. Serial increments wrap within the unsigned SOA range.

## Diagnosis, rebuild and stopping

**Diagnostics** checks local UDP/TCP authoritative SOA responses and shows their
serials. It also asks the two public recursive resolvers for NS answers and
compares them with the owner profile. Cached recursive answers do not prove
parent delegation, glue, DNSSEC or external network reachability. The panel never
accepts arbitrary probe addresses or commands from a customer.

**Rebuild zone** regenerates the selected zone and included-zone list from current
metadata, increments the serial, validates BIND and reloads it. It preserves
other zone files and does not infer missing customer records. Normal validation,
write or reload failure restores the selected file and previous included-zone
list, while the database transaction rolls back. Unpublished zones must remain
absent over both transports before success is reported.

For a service move, prepare and verify the replacement, change delegation and
allow caches to expire before choosing **Stop public hosting**. Type the exact
domain. Its records are retained but this public service stops answering
authoritatively for it. To return the whole service to private preview:

```sh
bash deploy/dns-public.sh --apply --private
```

All active public zones must be stopped first. Changing nameservers/interfaces
also requires stopping active zones. Private previews are rebuilt before restart;
conflicting records or failed validation preserve the previous profile. The
original private installer refuses to overwrite a public profile.

This remains bounded development tooling. Durable checkpoints now recover
interrupted publications from committed records; failed recovery pauses DNS
editing, profile changes and upgrades. Owner service repair, inactive-zone
removal and separate record snapshots are described in
[DNS_RECOVERY.md](DNS_RECOVERY.md). DNSSEC, public parent/glue diagnostics,
automatic mail records and multi-node recovery remain pending. Website files/SQL
archives do not include these separate DNS snapshots or a full DNS control-state
backup. Keep independent database/configuration recovery copies.

Configuration follows the [BIND configuration reference](https://bind9.readthedocs.io/en/v9.18.44/reference.html)
and its [validation tools](https://bind9.readthedocs.io/en/v9.18.44/manpages.html).
